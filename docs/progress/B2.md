### Merge notes (from the team merge plan)

**What B1 passes** (one better-sqlite3 connection at `DB_PATH`, PG's auth, one mount each):

```ts
import { createSowRouter, createDisputeRouter, SowStore } from "./sow";   // backend/src/sow
import { scoreDispute } from "./agent";                                      // backend/src/agent
import { getCaller, requireApiKey } from "./auth";                          // PG
const store = new SowStore(db);   // B1's Database instance (or a path; default DB_PATH, else ./data/app.sqlite). Pragmas untouched.
app.use(requireApiKey);           // optional, PG's X-API-Key check, applied by B1 at mount (the routers don't check it)
app.use(createSowRouter({ store, getCaller, isAuthorizedSigner /* PG/FE device-key registry */ }));  // /drafts/*
app.use(createDisputeRouter({ store, getCaller }));  // GET /deals/:id/sow, /deals/:id/agreement, /deals/:id/verify
```

| Dep | Router | Type | Default if omitted |
|---|---|---|---|
| `store` | both | `SowStore` | `new SowStore(db ?? DB_PATH)` |
| `db` | both | `Database \| string` (used only without `store`) | env `DB_PATH`, else `./data/app.sqlite` |
| `getCaller` | both | `(req) => string \| null` (PG's `getCaller(req, overrides?)` fits) | x-user-address **only** when `AUTH_DEV_HEADER=true`, else null → 401 |
| `isAuthorizedSigner` | sow | `(caller, signer) => boolean \| Promise<boolean>` | always false (only the wallet itself can sign) — FE signs with a **device key**, so pass PG/FE's registry |
| `verifyLink` | sow | `LinkVerifier` | RPC receipt check (swap for your indexer if you like) |
| `readDeal`, `readSettled` | dispute | chain readers | viem from `MST_RPC_URL` + `ESCROW_ADDRESS` (+ `DEPLOY_BLOCK`) |

**SowStore methods B1 calls** (exact names):
- `new SowStore(db | path)`
- `store.getSowForDeal(dealId)` → `{ sow, sowHash, draftId, version } | null` (dealId: number, numeric string or bigint)
- `store.saveRuling(reasoning, now?)` → `reasoningHash` (= `hashJson(reasoning)`); agent **and** arbitrator rulings; minimal arbitrator object `{ source: "arbitrator", dealId, sowHash, buyerBps, ruling }` (extras allowed and hashed). Throws on a malformed ruling.
- `store.getRuling(reasoningHash)` → the stored object | undefined
- `scoreDispute(input, { store })` (from `./agent`) stores the agent ruling itself and returns `{ scores, buyerBps, reasoningHash, model, promptVersion }`.

**Tables** (B2's alone; don't create these names): `drafts`, `sow_versions`, `agent_calls`, `dispute_rulings`. New columns are auto-added to old DBs.

**Routes**: B2 serves `GET /deals/:id/sow` + `GET /deals/:id/agreement` (FE calls the latter) and keeps `GET /deals/:id/verify`; B1 drops its own `/verify`. Mount order doesn't matter for B1's other `/deals/:id…` routes, since the paths differ.

**Env**: tests set `AUTH_DEV_HEADER=true` (`backend/vitest.config.ts`); production leaves it unset. `DEFAULT_DELIVERY_DAYS` (7) and `DEFAULT_REVIEW_SECS` (172800) are B2's, and are in `.env.example`.

### For B1 (backend: chain & data)

**Mounting:** see the merge notes above. Both routers parse JSON and map their own errors to `{ error: { code, message, details? } }`. Load `.env` before creating them, because they check their env at startup (`USD_ADDRESS`, `MST_RPC_URL`, `ESCROW_ADDRESS`, + `LLM_*` for merge-sow).

**Your `/deals/:id/resolve` route** calls `scoreDispute`, then the agent wallet sends `proposeResolution`:

```ts
import { scoreDispute, DisputeScoringError, DemoFallbackError, LlmUnavailableError } from "./agent"; // backend/src/agent
const linked = store.getSowForDeal(dealId);  // { sow, sowHash, draftId, version } | null
const ruling = await scoreDispute(
  { dealId, sow: linked.sow, sowHash,     // the linked draft's SOW + on-chain sowHash
    deliveryHash, evidenceHash,           // from getDeal
    complaint, deliveryNotes, evidenceNotes },
  { store },                              // optional; LLM chain + prompt v4 + fallbacks come from env
);
// → { scores, buyerBps, reasoningHash, model, promptVersion }  (the ruling is already stored under reasoningHash)
await agentWallet.writeContract({ functionName: "proposeResolution", args: [dealId, ruling.buyerBps, ruling.reasoningHash] });
// Errors: DisputeScoringError → 422 (e.issues), DemoFallbackError → 422, LlmUnavailableError → 502
```

**Arbitrator rulings.** `arbitrate()` leaves `proposedBuyerBps` stale by design, so the verifier uses the `Settled` event instead. Store the ruling so it's verifiable:

```ts
const reasoningHash = store.saveRuling({ source: "arbitrator", dealId, sowHash, buyerBps, ruling: "<text>" /* extras OK */ });
// then: arbitrate(dealId, buyerBps, reasoningHash)
```

**Link verification.** `/drafts/:id/link` reads the tx receipt over RPC (`backend/src/sow/verifyLink.ts`). It's injectable: `createSowRouter({ verifyLink: async ({ txHash, dealId, buyer, seller, amount, sowHash }) => ({ ok: true } | { ok: false, reason }) })`.

### For FE (frontend)

- **Shared package:** `cd shared && npm ci` first, then `npm install @kernel-exploits/shared@file:../shared` in `frontend/`, and copy `shared/dist/split.wasm` to `frontend/public/`. See `shared/README.md`. It exports `hashSow`, `hashJson`, `parseSow`, `computeBuyerBps`, `loadSplitWasm`, `verifyRuling` and the `Sow`/`Deliverable`/`Reasoning` types.
- **Endpoints:** `POST /drafts` (two-party body), `GET /drafts?address=`, `GET /drafts/:id`, `GET /drafts/:id/sow`, `POST /drafts/:id/{terms,merge-sow,conflicts,approve-sow,link}`, `PATCH /drafts/:id/terms`, `GET /deals/:id/{sow,agreement,verify}`. The shapes match `frontend/lib/types.ts` (Draft, Conflict, Signature, SowVersion) and are in `docs/API.md`. Identity is PG's session.
- **Signing:** `signMessage({ message: { raw: sowHash } })` with the device key → `approve-sow { party, version, signature, pin? }`. It's accepted when the signer is the wallet, or when PG's registry (`isAuthorizedSigner`) maps the device key to the wallet. `pin` is ignored by B2.
- **Conflicts:** `SowVersion.conflicts[]` (deliveryDeadline) must be settled first: each party `POST /drafts/:id/conflicts { party, field: "deliveryDeadline", value }`; equal values → a new version (sign that one). `approve-sow` returns 409 `ConflictsOpen` until then.
- **Before signing `proposeDeal` / `acceptDeal`:** recompute `hashSow(sow)` in the browser and refuse to sign if it differs from the server's `sowHash`. Use `approve-sow`'s `proposeDealArgs` as-is.
- **Verify page:** don't trust `/verify`'s `result`; recompute it in the browser.
  ```ts
  import { loadSplitWasm, verifyRuling } from "@kernel-exploits/shared";
  const wasm = await loadSplitWasm(await (await fetch("/split.wasm")).arrayBuffer()); // copy shared/dist/split.wasm to frontend/public/
  const { reasoning, sow } = await (await fetch(`${API}/deals/${id}/verify`)).json(); // data only
  const deal = await publicClient.readContract({ address: ESCROW, abi, functionName: "getDeal", args: [id] }); // straight from MST
  const result = verifyRuling({ reasoning, sow, wasm, onchainReasoningHash: deal.reasoningHash, onchainProposedBps: deal.proposedBuyerBps });
  // if Resolved, also pass settled: { toBuyer, amount: toBuyer + toSeller } from the Settled event
  ```
  Show ✅ when `result.ok`, and list each check: `hashMatches`, `bpsMatchesFormula`, `fulfilledMatches`, `bpsMatchesOnchain`, `settledMatches`, `wasmMatchesTs`, `sowMatches`.
- **Resolution screen (v4 `Reasoning`):** `/deals/:id/verify` returns `resolution[]`, one row per criterion with the SOW text, verdict, counts, **`basis`** and rationale. Use one table per deliverable. Columns: criterion, verdict (`met` / `partial s/t` / `not_met`), a **basis badge** (admission / undisputed / evidence), rationale, evidenceRefs, then the deliverable's computed `fulfilledPct` and weight. Show the split as `buyerBps / 100` % to the buyer. If `model` starts with `demo-fallback`, show a "demo ground truth" badge.

### Demo runbook

1. `cd backend && npm install`. Set `USD_ADDRESS` / `ESCROW_ADDRESS` from `deployments.md`, plus `DEMO_BUYER` and `DEMO_SELLER` (KYC'd demo wallets).
2. `npm run seed:demo`. This creates drafts `demo-A` … `demo-D`, already approved by both parties, and prints each `sowHash`, its ground-truth buyerBps and `proposeDealArgs`.
3. On stage, the buyer calls `POST /drafts/demo-A/approve-sow` → gets `proposeDealArgs` → signs `proposeDeal`. The seller signs `acceptDeal`. Then fund → deliver → dispute → `/resolve`.
4. **Stage settings:** with a working key, set `AGENT_FALLBACK_ON_FAILURE=true` (live model first, ground truth only if every model fails). With no key or unreliable network, set `AGENT_DEMO_FALLBACK=true` (ground truth, no LLM call). Either way the formula, hash, on-chain call and `/verify` are real, and `model` says `demo-fallback…` whenever the fallback ruled. **Never enable either flag outside the demo.**
5. Show `/deals/:id/verify` (✅), and scenario D to show that the injection has no effect.

### 00:20 — SOW draft/merge/approve router + LLM merge agent
- **What:** Express Router for the SOW negotiation (`/drafts`, `/drafts/:id`, `/seller-input`, `/merge-sow`, `/approve-sow`, `/link`) with SQLite storage and an LLM merge agent. The LLM writes only `title`, `deliverables`, `exclusions` and `conflicts`. The server fills in buyer, seller, amount, deadline, review window and token (`USD_ADDRESS`).
