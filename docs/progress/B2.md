### 02:30 — Gemini forced-mode check, transient backoff, model fallback
- **"auto mode" cause:** a label bug in the smoke script, not the request. `GeminiLlmClient` has no model-dependent branch and always sends `functionCallingConfig { mode: ANY, allowedFunctionNames: [fn] }`. On a 503 the SDK throws before the client records `lastCall`. The recorder read that missing `lastCall` as `forcedToolChoice: false` and printed "n/a, auto mode". Fixed: scripts print the client's *configured* `toolMode`, and failed tries show `model=… status=503 (transient) · mode=ANY…, no response`. A new test sends 5 model names, including the Claude ones the Anthropic client special-cases, and asserts mode ANY + allowedFunctionNames on each.
- **What:**
  - `agent/resilience.ts` `callWithFallback()`: per model, up to 3 tries on 429/500/503/network errors with backoff ~1 s → ~2 s (±25% jitter). Total sleep is capped at 10 s per call across all models. Then the next model in `LLM_FALLBACK_MODELS` is tried.
  - Non-transient errors (400, …) fail immediately, with no retry and no fallback.
  - This runs inside each validation attempt, so transient failures never use up the validation retry-once.
  - Every transient try is logged to `agent_calls` (`transient=1`, `status_code`, model).
  - When everything fails, the error reads e.g. `all LLM models failed: gemini-3.8-flash (503, 503, 503); gemini-3.7-flash (429, 429, 429); …` (a 502 from the router).
  - SDK built-in retries are disabled (Gemini `retryOptions.attempts: 1`, Anthropic `maxRetries: 0`) so there's only one retry layer and every try is visible.
  - The merge result's `model` and the scorer's `Reasoning.model` (hence `reasoningHash`) are the answering model.
  - `createLlmChain()` builds primary + fallbacks, and the router and `agent/index.ts` use it.
  - The smoke scripts print provider, mode, the model chain, each try's model and status, and `answered by`.
- **Files:** `backend/src/agent/{resilience,toolRetry,llm,geminiClient,anthropicClient,createLlmClient,index,mergeSow,scoreDispute}.ts`, `backend/src/sow/{router,store}.ts`, `backend/scripts/{_env,smoke-merge,smoke-score}.ts`, `backend/test/resilience.test.ts`, `.env.example`
- **How to use:** add `LLM_FALLBACK_MODELS=gemini-3.7-flash,gemini-flash-latest,gemini-2.5-flash` (names from `npm run models`). Nothing changes for B1.

### 00:20 — SOW draft/merge/approve router + LLM merge agent
- **What:** Express Router for the SOW negotiation (`/drafts`, `/drafts/:id`, `/seller-input`, `/merge-sow`, `/approve-sow`, `/link`) with SQLite storage and an LLM merge agent. The LLM writes only `title`, `deliverables`, `exclusions` and `conflicts`. The server fills in buyer, seller, amount, deadline, review window and token (`USD_ADDRESS`). If the model tries to set any of those, the server value is kept and the attempt shows up in `conflicts`. Validation uses `parseSow()`, with one retry that includes the errors, then 422. Weights are never normalised. Every merge is a new version, and approvals reset. `proposeDealArgs` is derived only from the stored, re-hashed SOW, and a past deadline or wrong token blocks it. Party text sits inside `<data>` blocks, and `</data>` is escaped. Every LLM attempt is logged to `agent_calls` (the key is never stored).
- **Files:** `backend/package.json`, `backend/tsconfig.json`, `backend/src/sow/{router,store,index}.ts`, `backend/src/agent/{llm,mergeSow}.ts`, `backend/test/sow.test.ts`, `docs/API.md`
