## Integration guide (for the final merge)

Everything B2 built, and how the other roles plug it in. B2's interfaces are defined in `docs/API.md`.

### For B1 (backend: chain & data)

**Mounting.** Both routers are self-contained Express routers: they parse JSON and map their own errors to `{ error: { code, message, details? } }`. Load `.env` before creating them, because they check their env at startup.

```ts
import { createSowRouter, createDisputeRouter, SowStore } from "./sow";   // backend/src/sow
const store = new SowStore(db);            // optional: share your better-sqlite3 connection (default: DB_PATH)
app.use(createSowRouter({ store }));       // /drafts/*   needs USD_ADDRESS, MST_RPC_URL, ESCROW_ADDRESS (+ LLM_* for merge-sow)
app.use(createDisputeRouter({ store }));   // GET /deals/:id/verify   needs MST_RPC_URL, ESCROW_ADDRESS (DEPLOY_BLOCK for Settled logs)
```

**Your `/deals/:id/resolve` route** calls `scoreDispute`, then the agent wallet sends `proposeResolution`:

```ts
import { scoreDispute, DisputeScoringError, DemoFallbackError, LlmUnavailableError } from "./agent"; // backend/src/agent
const ruling = await scoreDispute(
  { dealId, sow, sowHash,                 // the SOW of the linked draft (store.getSowForDeal(dealId)) + on-chain sowHash
    deliveryHash, evidenceHash,           // from getDeal
    complaint, deliveryNotes, evidenceNotes },
  { store },                              // optional; LLM chain + prompt v3 + fallbacks come from env
);
// → { scores, buyerBps, reasoningHash, model, promptVersion }
//   v3 scores: [{ id, fulfilledPct, criteria: [{ index, verdict: "met"|"partial"|"not_met", satisfied?, total?, rationale, evidenceRefs }] }]
await agentWallet.writeContract({ functionName: "proposeResolution", args: [dealId, ruling.buyerBps, ruling.reasoningHash] });
// Errors: DisputeScoringError → 422 (e.issues), DemoFallbackError → 422, LlmUnavailableError → 502
```

**Where the data lives.** B2's tables in the shared SQLite file (`DB_PATH`) are `drafts`, `sow_versions`, `agent_calls` (audit log of every LLM attempt, including 429s and retry delays) and `dispute_rulings` (full reasoning JSON keyed by `reasoningHash`). Don't create tables with these names.

**Arbitrator rulings.** `arbitrate()` leaves `proposedBuyerBps` stale by design, so the verifier uses the `Settled` event instead. Store the ruling so it's verifiable:

```ts
const ruling = { source: "arbitrator", dealId, sowHash, buyerBps, ruling: "<text>", arbitrator: "<address>" /* extra fields OK */ };
const reasoningHash = hashJson(ruling);                // from @kernel-exploits/shared
store.saveRuling(reasoningHash, dealId, ruling, now);  // then: arbitrate(dealId, buyerBps, reasoningHash)
```

**Link verification.** `/drafts/:id/link` currently reads the tx receipt over RPC (`backend/src/sow/verifyLink.ts`). At merge time, replace it with your indexer: `createSowRouter({ store, verifyLink: async ({ txHash, dealId, buyer, seller, amount, sowHash }) => ({ ok: true } | { ok: false, reason }) })`.

### For FE (frontend)

- **Endpoints:** `POST /drafts`, `GET /drafts/:id`, `POST /drafts/:id/{seller-input,merge-sow,approve-sow,link}`, `PATCH /drafts/:id/terms`, `GET /deals/:id/verify`. Send `x-user-address` until PG's auth lands. Shapes are in `docs/API.md`.
- **Before signing `proposeDeal` / `acceptDeal`:** recompute `hashSow(sow)` in the browser and refuse to sign if it differs from the server's `sowHash`. Use `approve-sow`'s `proposeDealArgs` as-is.
- **Verify page:** don't trust `/verify`'s `result`; recompute it in the browser.
  ```ts
  import { loadSplitWasm, verifyRuling } from "@kernel-exploits/shared";
  const wasm = await loadSplitWasm(await (await fetch("/split.wasm")).arrayBuffer()); // copy shared/dist/split.wasm to frontend/public/
  const { reasoning, sow } = await (await fetch(`${API}/deals/${id}/verify`)).json(); // data only
  const deal = await publicClient.readContract({ address: ESCROW, abi, functionName: "getDeal", args: [id] }); // straight from MST
  const result = verifyRuling({ reasoning, sow, wasm, onchainReasoningHash: deal.reasoningHash, onchainProposedBps: deal.proposedBuyerBps });
  // if Resolved, also pass settled: { toBuyer, amount: toBuyer + toSeller } from the Settled event
  ```
  Show ✅ when `result.ok`, and list each check: `hashMatches`, `bpsMatchesFormula`, `fulfilledMatches`, `bpsMatchesOnchain`, `settledMatches`, `wasmMatchesTs`, `sowMatches`.
- **Resolution screen (v3 `Reasoning`):** use one table per deliverable, with rows = acceptance criteria (the text is `sow.deliverables[i].acceptanceCriteria[c.index]`). Columns: verdict (`met` / `partial s/t` / `not_met`), rationale, evidenceRefs, then the deliverable's computed `fulfilledPct` and weight. Show the split as `buyerBps / 100` % to the buyer. If `model` starts with `demo-fallback`, show a "demo ground truth" badge.

### Demo runbook

1. `cd backend && npm install`. Set `USD_ADDRESS` / `ESCROW_ADDRESS` from `deployments.md`, plus `DEMO_BUYER` and `DEMO_SELLER` (KYC'd demo wallets).
2. `npm run seed:demo`. This creates drafts `demo-A` … `demo-D`, already approved by both parties, and prints each `sowHash`, its ground-truth buyerBps and `proposeDealArgs`.
3. On stage, the buyer calls `POST /drafts/demo-A/approve-sow` → gets `proposeDealArgs` → signs `proposeDeal`. The seller signs `acceptDeal`. Then fund → deliver → dispute → `/resolve`.
4. **Stage settings:** with a working key, set `AGENT_FALLBACK_ON_FAILURE=true` (live model first, ground truth only if every model fails). With no key or unreliable network, set `AGENT_DEMO_FALLBACK=true` (ground truth, no LLM call). Either way the formula, hash, on-chain call and `/verify` are real, and `model` says `demo-fallback…` whenever the fallback ruled. **Never enable either flag outside the demo.**
5. Show `/deals/:id/verify` (✅), and scenario D to show that the injection has no effect.

| B seller wins | Portfolio fully delivered; complaint is about colours (not in SOW) | all met | **0** | 0–300 |

### 00:20 — SOW draft/merge/approve router + LLM merge agent
- **What:** Express Router for the SOW negotiation (`/drafts`, `/drafts/:id`, `/seller-input`, `/merge-sow`, `/approve-sow`, `/link`) with SQLite storage and an LLM merge agent. The LLM writes only `title`, `deliverables`, `exclusions` and `conflicts`. The server fills in buyer, seller, amount, deadline, review window and token (`USD_ADDRESS`).
